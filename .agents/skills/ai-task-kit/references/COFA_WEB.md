# Cofa 웹 IDE에서 웹 과제 실행·확인 (공식 가이드에 기반한 참고)

**사용 범위:** AI와 공개 도구 사용이 허용된 과제 수행 단계에서만. 공식 Cofa 지침·실제 과제 README가 우선한다. 감독, 접속 제한, 네트워크 경로를 우회하는 방법이 아니다. 웹 서비스 과제가 아닐 때는 필요 없다.

## 실행 순서

1. 과제의 `README`·`package.json` 등에서 기존 실행 방법과 필요한 런타임 확인. 스택을 임의로 갈아엎지 않는다.
2. 해당 프로젝트의 승인된 개발 서버 명령을 실행한다. 서버가 출력하는 **실제 포트**를 확인한다.
3. 공식 가이드의 Browser 미리보기 연결을 위해 서버가 `0.0.0.0`으로 바인딩되게 설정한다. 앱이 `localhost`로만 듣는 경우 Cofa Browser에 나타나지 않을 수 있다. **외부 터널·포트포워딩·접속 제한 우회는 하지 않는다.**
4. Cofa 내부 Browser 도구의 PORT에 실제 포트를, URL 영역에 경로(`/` 또는 `/dashboard` 등)를 입력하고 새로고침한다.
5. 화면이 표시되면 **입력·버튼·화면 이동·저장 등 핵심 기능을 사람이 직접 확인**한다. 웹 서버를 실행한 터미널은 미리보기하는 동안 종료하지 않는다.

```text
기존 프로젝트 README → 승인된 서버 실행 → 실제 포트 확인
        ↓
Cofa Browser의 PORT / URL 경로 입력
        ↓
화면이 뜨면 핵심 기능 직접 확인 → 실제 결과 기록
```

## 오류별 확인 순서

| 증상 | 먼저 확인할 것 |
|---|---|
| 서버에 응답이 없음·`ECONNREFUSED` | 터미널에서 서버가 살아 있는가, 실제 포트가 일치하는가 |
| `EADDRINUSE` · `Address already in use` | 같은 포트를 다른 실행 중인 프로세스가 사용 중인가; 임의로 프로세스를 종료하지 않는다 |
| 페이지는 열리는데 404 | 실제 서비스 경로(`/`, `/api` 등)가 맞는가 |
| 화면이 갱신되지 않음 | 코드 저장·서버 실행·브라우저 새로고침 순서를 확인 |
| 메모리 부족·서버 종료 | 로그·CPU/RAM 사용량·실행 설정을 확인하고 최소 변경 후 재실행 |
| Cofa Browser·감독·접속 자체 장애 | 과제 프로그램 문제와 구분해 플랫폼 내 **문제 신고** 이용 |

`explain` 명령은 로그 텍스트의 흔한 오류 단어를 바탕으로 **가능한 원인과 조사 순서**만 제공한다. 원인 확정이나 서버 자동 재시작 기능은 없다.

**검증 한계:** 프로그램의 로컬 문법/파일 검사는 실제 Browser 동작을 보장하지 않는다. Cofa에서 실제 동작 여부는 허용된 환경에서 직접 확인해야 하며, 이 문서는 해당 플랫폼 접근이나 호환성 시험을 수행했다는 뜻이 아니다.
