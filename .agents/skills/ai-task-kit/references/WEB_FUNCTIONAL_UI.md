# 웹 화면 지침 — 기능 우선, 디자인은 최소

**웹페이지 구현이 실제 요구사항인 경우에만** P05에서 이 문서를 한 번 읽는다. 비웹 과제에는 읽거나 적용하지 않는다. 모든 시험이 웹 과제라고 가정하지 않는다. **실제 과제 지침이 우선**이며, 지정한 디자인·화면·접근성 조건도 필수 요구사항이면 생략하지 않는다.

## 1. 먼저 작동하는 화면
과제의 필수 요구를 `입력 → 실행 → 결과`에 연결하고 가장 중요한 흐름 하나부터 실제로 작동시킨다. 기존 기술 스택·컴포넌트·기존 CSS를 우선 사용하며, 디자인 때문에 앱을 재작성하지 않는다. 첫 실행 이후 나머지 필수 기능을 확장한다.

검색·등록·저장·다운로드는 요구된 것만 실제 처리와 연결한다. 화면만 보이는 버튼이나 고정된 예시 숫자를 기능 완료로 보고하지 않는다. 실제 데이터가 없으면 임의로 결과를 만들지 않고 입력 필요·결과 없음 상태를 표시한다. 테스트용 예제는 예제라고 구분한다. 보고서·폼·목록 등 요구에 맞는 배치를 선택하고 모든 과제를 대시보드로 만들지 않는다.

## 2. 최소한의 화면 기준
- 제목과 간단한 안내, 입력·조건, 주요 버튼, 결과 순으로 정리하되 과제의 지정 배치가 있으면 따른다. 필요하지 않은 메뉴·카드·차트는 추가하지 않는다.
- 읽기 쉬운 글자와 충분한 배경 대비, 일관된 간격·버튼 모양을 사용한다. 입력에는 명확한 라벨, 표에는 열 이름을 둔다. 작은 글자나 흐린 설명으로 필수 정보를 숨기지 않는다.
- 키보드 이동과 선택 표시를 유지하고, 오류를 색상만으로 전달하지 말고 이유와 수정 방법을 문장으로 쓴다.
- 사용할 화면 폭에서 입력·버튼의 잘림·겹침을 수정한다. 넓은 표는 필요한 영역에서 스크롤할 수 있게 한다. 별도 모바일 화면 제작은 과제가 요구할 때만 검토한다.
- 애니메이션·다크모드·그라데이션·장식은 선택 사항이며 기본 구현에 넣지 않는다. 디자인만을 위해 새 라이브러리·외부 폰트·아이콘 CDN·이미지 생성·외부 디자인 서비스를 추가하지 않는다. 이미 제공된 구성은 재사용한다.

## 3. 필요한 상태만 처리
해당 기능에 실제로 해당하는 상태만 구현한다. 입력 전에는 사용 방법, 처리 중에는 진행 표시와 필요한 중복 실행 방지, 결과 없음에는 빈 결과 안내, 입력 오류에는 원인·수정 방법, 정상 결과에는 실제 처리 결과를 보여준다. 무관한 상태나 기능을 새로 만들지 않는다.

## 4. 기능 확인 후 마무리
변경한 기능부터 실행·테스트하고, 제출 전 필수 동작과 저장 결과를 종합 확인한다. 서버 실행 성공이나 화면 표시만으로 전체 기능이 검증됐다고 판단하지 않는다. 화면의 조작·표시 상태는 사용자가 Cofa 내부 Browser에서 직접 확인하도록 짧게 안내한다. 직접 확인하지 못한 화면 동작은 `UNVERIFIED`로 남기고, 사용자 확인과 자동 테스트 결과를 구분한다.

Computer Use·감독 우회·시험 화면/자료의 외부 전송·자동 제출은 하지 않는다. 읽기·실행이 제한되면 우회하지 않는다. 최종 저장·제출 목록과 제출 버튼은 사용자가 직접 확인한다. 이 문서는 구현 지침이며 실제 앱, 접근성 인증 또는 성능 검증 결과가 아니다.
