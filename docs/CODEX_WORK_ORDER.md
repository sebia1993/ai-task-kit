## 1. 범위와 우선순위

P0: 핵심 Skill, 직접 읽기 부트스트랩, 한국어 판단 안내, 과제/도구 경로 분리, 원본 보호, 검사 결과의 정직한 구분.

P1: CSV/JSON 검사·합계·날짜·고유값, 파일/문법 검사, 로컬 시간·오류 재시도, 오류 힌트.

유보: 특정 웹 프레임워크/DB 설치, 대형 Python 레포 병합, 자동 멀티에이전트, 배포/브라우저 자동화. 문제에 필요하면 과제의 기존 환경에서 Codex가 작업하고 도구에 영구 의존성으로 추가하지 않는다.

## 2. 지켜야 할 계약

- Python 3.10+ 표준 라이브러리만 사용. 검사 도구는 HTTP·socket·외부 프로세스를 실행하지 않는다.
- 네트워크가 없는 것과 모든 도구의 네트워크를 차단하는 것은 다르다. 샌드박스라고 광고하지 않는다.
- 입력 자료는 읽기 전용. 상태 기록은 명시된 과제 루트 아래 `.ai-task-kit/session.json`만 사용한다.
- 문법 검사/파일 존재와 실제 기능 테스트를 구분한다. `verify`가 성공 모양의 파일만 보고 과제 완료를 선언하면 회귀 결함이다.
- 미검증=UNVERIFIED, 실패=FAIL, 범위 내 성공=PASS. 종료 코드 2를 실패 은폐용 0으로 바꾸지 않는다.
- 누락·중복·날짜·금액의 업무적 의미는 사용자 판단 대상이다. 열 누락을 `.get(..., 0)`로 덮지 않는다.
- 루트 경로 이탈·링크·특수 파일·파일/행/탐색 한도에 대한 테스트를 유지한다.
- 공식 타이머가 우선한다. 같은 세션을 다시 시작해 시간을 초기화하지 않는다. 로컬 추정은 자동 알람이 아니다.
- Skill의 지침은 사용자/공식 과제/플랫폼 권한을 바꾸지 못한다. 불허 명령의 다른 실행 경로를 찾지 않는다.

## 3. 후속 검증 절차

① 기준 테스트

```bash
python3 -m unittest discover -s tests -v
python3 kit.py doctor --root . --json
```

② 독립 패키지: `.agents/skills/ai-task-kit`만 새로운 폴더에 복사하고 그 안의 `scripts/taskkit.py`로 doctor/audit를 실행한다. 루트 저장소에 몰래 의존하지 않는지 확인한다.

③ 모델 평가: 시험 전 공개 합성 과제에서 기본 Codex와 Kit 적용 Codex를 같은 모델·권한·시간·입력으로 비교한다. 신선한 작업 폴더와 별도 세션을 사용한다. 코드 테스트 수가 아니라 실제 요구사항 충족·완료 시간·잘못된 성공 선언·사용자 개입을 기록한다. 시험 문제·사용자 메일을 공개 테스트 데이터로 쓰지 않는다.

④ Cofa 사전 체험: 허용 여부, clone/파일 읽기, 승인 흐름, 과제 경로, Python 버전, 저장·미리보기·제출 흐름을 사용자가 직접 점검한다. 모델에게 화면을 자동 조작하도록 시키지 않는다. 15분은 대화의 기존 안내 요약이며 최신 공식 안내를 다시 우선한다.

⑤ 결과는 `docs/VALIDATION.md`에 날짜·명령·환경·실제 출력·미검증을 분리해 기록한다. 실제 수행하지 않은 A/B·현장 검증은 NOT RUN이다.

## 4. 기능 확장 허용 기준

추가 기능은 설치 비용보다 시간을 절약하고, 명확한 자동 테스트가 있으며, 원본 보호와 규정 경계를 해치지 않을 때만 채택한다. 이미 통과한 기능의 불필요한 재작성이나 추측에 의한 패키지 설치는 하지 않는다. 오래 걸리는 설치 실패는 기본 Codex로 전환하는 경로를 유지한다.

## 5. 완료 보고 형식

구현한 기능 / 실행한 검증 명령과 결과 / 실행하지 못한 검증 / 변경 파일 / 남은 위험을 보고한다. 합격 보장·점수 상승률을 만들지 않는다. 독립 리뷰어 없이 자가 리뷰한 경우 그 사실을 명시한다.
