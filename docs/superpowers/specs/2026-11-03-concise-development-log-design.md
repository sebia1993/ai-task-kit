# 간결한 개발 판단 기록 설계

## 승인된 목표

사용자가 요청한 중요한 질문·AI 답변·판단 근거를 짧은 Markdown으로 남긴다. 개발 중 무엇을 선택했고 어떻게 확인했는지 빠르게 복기할 수 있게 한다. 대화 전문과 사소한 수정 이력은 수집하지 않는다.

## 선택한 구조

- 공개 Skill에는 기록 지침과 빈 양식만 포함한다.
- 사용자가 기록을 요청하면 작업 AI가 허용된 TASK의 `.ai-task-kit/DEVELOPMENT_LOG.md`를 직접 갱신한다. 별도 CLI·서버·자동 대화 수집기는 추가하지 않는다.
- 상단 요약은 최대 5개 항목, 판단별 이력은 제목과 6개 짧은 항목으로 쓴다. 중요한 결정·검증 결과 변경 때만 갱신한다.
- 질문/답변, 선택 주체, 이유, 구현 위치, 검증 근거, 한계를 연결한다. AI 제안·사용자 명시 결정·AI 자율 결정·미결정을 구분한다.
- 관찰한 실행 결과·사용자 확인 보고·미실행을 구분하고, 이전 결론이 바뀌면 연결된 새 항목을 남긴다. 사후 해석은 당시 근거와 구분한다.
- 기존 `worklog` JSON은 선택적으로 유지한다. 이미 기록한 ID를 연결할 수 있지만 두 파일을 같은 내용으로 관리하지 않는다.

## 경계와 읽기 비용

기록을 요청한 경우에만 상세 안내와 양식을 읽는다. clone만으로 활성화되거나 이전 채팅을 수집하지 않는다. 기존 개발 현황 보고는 별도 파일 없이 그대로 동작한다. 새 세션에서는 상단 요약과 최근 항목부터 읽고 현재 파일 상태를 다시 확인한다.

실제 과제 대화·원문·결과를 KIT나 공개 Git에 넣지 않는다. KIT의 `.gitignore`는 TASK의 Git 추적이나 플랫폼 제출 제외를 보장하지 않는다. 기록 위치가 허용되지 않으면 파일 기록만 생략하고 과제 작업은 계속한다. 후속 AI 금지 단계의 답안 생성과 이해도·성능 향상 보장은 범위 밖이다.

## 검증 기준

기존 177개 회귀 테스트, 새 문서의 링크·형식·길이, 깨끗한 복사본 및 독립 Skill을 확인한다. 작성자 검토와 독립 리뷰를 구분하고, 합성 근거로 기록 작성 지침을 제한적으로 점검한다. 실제 Cofa/Codex 동작·모델 비교·학습 효과는 실행하지 않으면 NOT RUN으로 남긴다.
