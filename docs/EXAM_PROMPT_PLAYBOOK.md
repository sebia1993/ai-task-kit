# Cofa 과제 수행용 공개 프롬프트 플레이북

> **용도:** AI 사용이 허용된 2차 예선 **과제 수행 단계**에서, Cofa 응시 환경에 제공된 Codex가 문제를 정확히 이해하고 구현·검증하도록 돕는 **범용 작업 지시 템플릿**입니다. 실제 문제의 정답, 선작성 결과물, 자동 제출 프로그램이 아닙니다. 이 저장소는 Cofa·대회 운영사의 공식 도구가 아닙니다.

## A. 운영팀 안내에 따른 사용 경계 (2026-10-29 확인 내용 요약)

- **개인 PC의 클립보드에 미리 저장한 문구를 응시 환경에 붙여넣지 않습니다.** 외부 메모를 보면서 타이핑하는 방식도 허용되지 않습니다.
- **공개 GitHub 저장소에 사전 제작해 둔 프롬프트 템플릿을, 허용된 응시 환경에서 가져와 사용하는 것은 가능**하다고 운영팀이 안내했습니다. 사용한 저장소는 **2차 예선 결과를 통지받을 때까지 계속 공개** 상태를 유지해야 합니다. 비공개 저장소의 자료는 사용하지 않습니다.
- 응시 환경 안에서 과제 내용을 읽고 **직접 새 지시문을 작성하는 행위**는 허용됩니다. 이 문서는 **응시 환경 내에서 가져와 파일로 읽는 방식**을 전제로 합니다.
- 시험 문제·자료·결과물·업무 대화·로그 등 비공개 내용을 공개 저장소나 외부 서비스에 업로드하지 않습니다. Git Push·외부 AI/API 키 연결·보안/감독 우회·Computer Use·자동 제출을 하지 않습니다.
- 외부 자료로 **결과물 전체를 대체하지 않습니다.** 공식 과제 README, 지정 산출물, 제공된 도구·권한·감독 규칙이 항상 우선합니다. 제출물과 작업 이력은 검토 대상입니다.
- **후속 서술형 등 AI 사용이 금지된 단계에서는 이 문서와 Codex를 사용하지 않습니다.** 시험 플랫폼의 해당 단계 규칙을 따릅니다.
- 공식 가이드 상세 9장 및 실제 시험 화면의 최신 조건이 여기 적힌 내용보다 우선합니다. 특정 프롬프트가 허용되는지 애매하면 실행하지 않고 Cofa Helper 또는 운영팀에 확인합니다.

## B. 응시 환경에서 이용하는 방법

1. **공개 저장소 사용이 실제 과제에서 허용되는 경우에만**, 응시 환경의 허용된 터미널/저장소 기능으로 [공개 저장소](https://github.com/sebia1993/ai-task-kit)를 가져옵니다. 먼저 현재 위치가 실제 과제 폴더 밖이고 별도 도구 위치가 허용되는지 확인합니다. **과제 폴더나 그 하위에서는 clone하지 않습니다.** 예시:
   ~~~bash
   git clone --depth 1 https://github.com/sebia1993/ai-task-kit.git ai-task-kit
   ~~~
   가져오기가 차단되거나 과제 폴더와 도구 폴더를 구분할 수 없다면 제한을 우회하지 말고 기본 Codex를 사용합니다. 이미 과제 안에 도구가 있으면 임의로 삭제·이동하지 말고 최종 제출 대상 혼입 여부를 확인합니다.
2. **응시 환경 안에서 직접 작성한** 지시로, 제공된 Codex에게 **`BOOTSTRAP.md` 하나를 시작점**으로 읽도록 요청합니다. BOOTSTRAP이 아직 확인하지 않은 Skill과 플레이북을 최초 한 번만 읽도록 안내합니다. 예:
   > ai-task-kit/BOOTSTRAP.md를 읽고 현재 과제에 필요한 지침을 스스로 선택해 적용해줘. 최초 로드의 커밋·지침 파일 경로는 확인한 경우에만 알려주고, 답변마다 적용 지침과 실제 수행 근거를 표시해줘.
3. 사용자는 매번 **P01~P12를 지정할 필요가 없습니다.** Codex가 실제 과제 진행 상태에 맞춰 지침을 전환합니다. 같은 세션에서 이미 확인한 Skill·플레이북은 중복해서 읽지 않습니다. 특정 상황만 다시 요청할 때 번호를 직접 지정할 수 있습니다. 모든 지침을 한꺼번에 적용하지 않고, 과제 파일을 도구 폴더로 옮기지 않습니다.
4. Codex가 파일을 직접 읽을 수 없는 경우, 접근을 우회하거나 외부 메모에서 옮겨 적지 않습니다. 허용된 응시 환경에서 직접 지시문을 작성하여 진행합니다.

**중요:** 여기 있는 문구를 *시험 전에 개인 PC에서 복사해 두거나, 시험 중 외부 화면·메모를 보면서 다시 입력하는 절차*는 사용하지 않습니다. 허용된 응시 환경에서 **공개 파일을 직접 가져와 읽는 것**과 구분해야 합니다.

### 도구 폴더·과제 폴더 분리 및 최초 버전 기록

~~~text
허용된 작업 영역/           (단지 설명을 위한 구조)
├─ 과제 폴더/             실제 과제 README·제출 파일
└─ ai-task-kit/          공개 지침 및 검사 도구
~~~

현재 디렉터리가 과제 폴더인지 먼저 확인합니다. KIT를 TASK와 분리할 수 있다는 것이 확인된 경우에만 허용된 위치에서 clone합니다. **KIT가 TASK 안에 있으면 임의로 삭제하거나 옮기지 않으며, `.gitignore`만으로 실제 제출에서 제외됐다고 판단하지 않습니다.** Cofa 제출 대상 화면을 직접 확인해야 합니다.

최초 한 번 문서를 실제로 읽은 다음, Git 명령이 허용될 경우 아래 **로컬 읽기 명령**으로 버전을 확인할 수 있습니다. `<KIT>`는 실제 도구 폴더의 경로입니다.

~~~bash
git -C "<KIT>" rev-parse --verify HEAD
git -C "<KIT>" status --porcelain -- BOOTSTRAP.md .agents/skills/ai-task-kit/SKILL.md docs/EXAM_PROMPT_PLAYBOOK.md
~~~

첫 명령에서 성공한 실제 HEAD SHA만 커밋으로 기록합니다. 두 번째 명령이 성공해 **출력이 없을 때만** 관련 지침 파일에 변경이 없다고 표시합니다. 성공 결과를 확인하지 못했으면 **미확인**입니다. 커밋 확인과 실제 파일 읽기는 별개이며, Git이 없거나 명령이 불허되면 건너뜁니다. 보고 예시:

```text
초기 로드: docs/EXAM_PROMPT_PLAYBOOK.md | 커밋: <확인한 SHA 또는 미확인> | 지침 파일 변경: 없음/있음/미확인
```

이 정보는 **최초 로드에 한 번만 보고**합니다. 매 응답에서는 기존의 짧은 두 줄 적용 내역 보고만 유지합니다. 같은 세션에서 이미 읽은 지침은 반복해서 열지 않습니다. 응시 환경이나 세션이 바뀌어 읽기 근거가 사라지면 파일을 다시 확인하거나 읽기 미확인으로 표시합니다.

## B-1. Codex가 자동으로 선택하고 응답마다 적용 내역 표시

이 문서가 **응시 환경 내부에서 실제로 읽힌 경우에만** Codex는 과제의 요구·파일·오류·검증 상태에 따라 P01~P12 중 해당 지침을 스스로 선택한다. 사용자가 P번호를 기억하거나 매번 지정하지 않아도 된다. 같은 세션에서 이미 확인한 내용은 다시 읽지 않고 재사용하며, P01이 다른 지침의 반복 로드를 유발해서는 안 된다.

- 과제 시작에는 **P01**, 업무 기준이 불명확하면 **P02**, 구현·수정에는 **P03**, CSV/JSON 분석에는 **P04**, 웹 실행에는 **P05**를 선택한다.
- 오류가 발생해 조사할 때 **P06**, 실제 기능을 검증할 때 **P07**, 제출용 문서가 요구될 때만 **P08**, 제출 전 점검에는 **P09**를 선택한다.
- 작업 재개에는 **P10**, 공식 화면에서 시간이 부족한 것을 확인하면 **P11**을 선택한다. 공개 도구 접근 문제의 **P12**는 이미 문서를 읽은 상황에서만 적용하고, 읽지 못했으면 적용 지침 없이 기본 Codex로 계속한다.
- 현재 수행할 작업에 맞는 지침 보통 1~2개, 복합 작업에 최대 3개까지 선택한다. 상황이 바뀌면 스스로 전환한다. 단순히 파일을 읽기만 했거나 아직 수행하지 않은 항목은 '적용'으로 표시하지 않는다.

### 매 응답 끝에 붙이는 두 줄 — 실제 근거까지 표시

```text
적용 지침: P04(자료 분석), P07(검증) | 플레이북: 읽기 확인
수행 근거: CSV 구조 검사 실행 및 출력 확인 | 검증: PASS(해당 검사만)
```

실제로 플레이북을 읽지 못한 경우는 다음처럼 구분한다.

```text
적용 지침: 없음 | 플레이북: 로드 실패(또는 읽기 미확인)
수행 근거: 실행 없음 | 검증: UNVERIFIED
```

- **읽기 확인**은 `docs/EXAM_PROMPT_PLAYBOOK.md`의 내용이 실제 파일 읽기 결과에 반환된 경우에만 쓴다. 저장소 경로만 알고 있거나 이전 대화에서 읽었다는 주장만으로 확인 처리하지 않는다. 연결이 끊겨 세션이 바뀌었다면 재조회하거나 **읽기 미확인**이라고 표시한다.
- **수행 근거**에는 실제 수정한 파일·실행 명령·확인한 출력 등을 한 가지만 짧게 쓴다. 아직 실행하지 않았으면 `수행 근거: 실행 없음 | 검증: UNVERIFIED`. 단순 파일 검사·문법 확인을 기능 검증 완료라고 표시하지 않는다.
- 이 두 줄은 Codex의 **자기 보고**이며, 독립적인 실행 확인·지침 준수 보증 시스템이 아니다. 실제 도구 출력 및 변경된 파일과 교차 확인하면 신뢰성을 높일 수 있다.
- 공식 시험 규칙과 후속 AI 금지 단계가 우선한다. **AI 금지 단계에는 적용 내역 보고를 포함한 AI 지원도 하지 않는다.**

## C. 상황 선택표

| 번호 | 이런 상황일 때 | 무엇을 기대하나 |
|---|---|---|
| **P01** | 과제를 처음 받았을 때 | 문제·산출물·검증 기준 파악 및 우선순위 결정 |
| **P02** | 조건이 애매하거나 서로 충돌할 때 | 업무 담당자에게 확인할 핵심 질문 추출 |
| **P03** | 구현을 시작하거나 기존 코드를 수정할 때 | 최소 변경으로 기능 구현·동작 확인 |
| **P04** | CSV/JSON 데이터 집계·분석 과제일 때 | 누락·중복·합계·날짜 등 자료 검산 |
| **P05** | 웹 서비스/화면 구현 과제일 때 | 기존 서버 실행 및 Cofa Browser에서 미리보기 |
| **P06** | 명령·프로그램이 실패할 때 | 실제 오류 근거로 원인 좁히고 재검증 |
| **P07** | 기능을 만들었지만 맞는지 확신이 없을 때 | 요구사항별 검증 근거 수집 |
| **P08** | 계획서·보고서·협업 기록이 필요할 때 | 실제 작업 과정에 근거한 문서 작성 |
| **P09** | 제출 전에 빠진 것이 없는지 확인할 때 | 파일·형식·미검증 사항 최종 점검 |
| **P10** | 도중에 연결이 끊기거나 대화가 중단됐을 때 | 실제 파일 상태부터 확인해 안전하게 재개 |
| **P11** | 공식 타이머상 시간이 부족해졌을 때 | 새 개발보다 필수 결과·검증·제출 준비 우선 |
| **P12** | GitHub·Skill·패키지 설치 등이 막힐 때 | 우회 없이 기본 작업 경로로 전환 |

## D. 상황별 프롬프트

아래 코드 블록은 **Cofa 응시 환경에 허용된 방식으로 가져온 파일을 Codex가 읽을 때 참조할 내용**입니다. 사용자에게 클립보드 붙여넣기를 요구하는 문서가 아닙니다. 각 프롬프트에서 말하는 '과제'는 **현재 응시 환경에 실제로 제공된 과제**입니다.

### P01. 시작 — 문제를 먼저 이해하고 필수 기능부터

~~~text
현재 응시 환경에서 허용된 Codex만 사용해줘.
먼저 실제 과제 README·지시문·기존 파일을 읽어줘. BOOTSTRAP과 Skill, 플레이북을 같은 세션에서 이미 읽었다면 다시 읽지 말고 적용해줘. 읽기 여부가 미확인일 때만 필요한 문서를 확인해줘.
공식 규칙과 실제 과제 지침을 항상 우선하고, 도구 폴더와 과제 폴더를 구분해줘.
[목표] [필수 제출물/경로] [성공 판단 기준] [모호한 업무 조건] [첫 실행·검증 방법]을 쉬운 한국어로 짧게 정리해줘.
이후 필수 기능부터 작업을 시작하고, 사소한 개발 선택은 스스로 처리해줘.
다만 계산 기준 변경·입력 제외·원본 덮어쓰기 등 결과에 큰 영향을 주는 선택만 이유와 함께 확인해줘.
검증하지 않은 기능은 완료라고 하지 말고, 최종 제출은 내가 직접 하도록 남겨줘.
~~~

### P02. 업무 조건이 모호할 때 — 담당자에게 물을 질문

~~~text
현재 과제에서 해석이 모호하거나 서로 충돌하는 조건을 찾아줘.
먼저 README·기존 메시지·자료에서 근거를 찾아서 [확정된 사실]과 [아직 답이 없는 질문]을 구분해줘.
답이 없어 결과가 달라질 수 있는 질문은 중요도 순으로 최대 3개만 작성해줘.
각 질문에 왜 답이 필요한지 한 문장으로 설명하고, 실제 업무 담당자에게 보내는 행위는 내가 직접 하게 해줘.
답변을 임의로 만들지 말고, 그 조건과 무관한 구현은 계속 진행해줘.
~~~

### P03. 실제 구현 — 기존 구조 유지·최소 변경

~~~text
과제의 기존 기술 스택·파일 구조·실행 명령을 먼저 확인해줘.
필수 요구사항을 작은 단위로 나누되, 새 프레임워크나 외부 패키지는 필요성이 입증된 경우에만 검토해줘.
기능 하나를 구현할 때마다 변경 파일, 실제 실행 방법, 예상 결과와 실제 결과를 확인해줘.
원본 입력·공식 테스트를 바꾸어 실패를 숨기지 말고, 중요한 문제부터 끝내줘.
다음 단계는 별도의 재승인 없이 진행하되 실제 플랫폼의 권한 요청과 중요한 업무 판단은 내가 확인하게 해줘.
~~~

### P04. CSV/JSON 데이터 과제 — 숫자와 자료의 신뢰성

~~~text
실제 과제 데이터의 열·키·자료 종류·행 수부터 확인해줘.
중복, 결측, 날짜 형식, 합계와 계산 기준이 결과에 미치는 영향을 구분해서 설명해줘.
결측을 임의로 0으로 바꾸거나 중복을 자동 제거하지 말아줘. 처리 기준이 미확정이면 담당자 확인 질문으로 남겨줘.
필요하고 지원되는 경우에만 ai-task-kit의 audit로 CSV/JSON 구조를 보조 검증해줘.
실제로 계산한 값·독립 검산값·차이가 나는 원인·남은 미확인 사항을 간결하게 정리해줘.
~~~

### P05. 웹 서비스 과제 — Cofa Browser 확인

~~~text
기존 README·package.json 등에서 실행 명령과 실행 포트를 먼저 찾아줘.
허용된 환경에서 웹 서버를 실행하고, Cofa Browser 미리보기에 맞게 실제 포트·경로·서버 바인딩 상태를 확인해줘.
필요한 경우 프로젝트 지침에 맞춰 0.0.0.0 바인딩을 사용하되 외부 터널·접속 제한 우회는 하지 말아줘.
화면이 열린다는 것만으로 완료라고 하지 말고, 입력·버튼·화면 이동·결과 저장처럼 과제에서 요구한 핵심 기능을 확인해줘.
직접 확인하지 못한 화면 동작은 미검증으로 표시하고, 문제는 서버 오류→포트→바인딩→경로 순서로 조사해줘.
~~~

### P06. 오류 해결 — 같은 시도 반복 금지

~~~text
방금 실패한 명령과 실제 오류 출력, 영향을 받은 파일·위치를 먼저 확인해줘.
확인된 사실과 추측을 나누고, 가장 가능성이 큰 원인 하나에 대해 최소한의 수정만 적용한 뒤 동일 조건에서 재실행해줘.
같은 오류가 두 번 반복되면 이전 가정을 재평가하고 다른 해결 방법 또는 기능을 축소한 대안을 제시해줘.
필요한 경우에만 ai-task-kit의 retry 명령으로 실패 횟수를 수동 기록해줘. 자동 실행·권한 우회·반복 설치는 하지 말아줘.
실패가 지속되면 미해결 상태와 현재까지 실제 확인한 사실을 짧게 보고해줘.
~~~

### P07. 검증 — 파일이 있다는 것과 동작한다는 것을 구분

~~~text
현재 요구사항을 [요구 → 구현 파일/기능 → 검증 명령/방법 → 실제 결과 → 남은 한계]로 연결해줘.
가능한 경우 기존 테스트·작은 예제·경계값으로 실제 실행 결과를 검증하고 입력이나 공식 테스트를 수정하지 말아줘.
파일 존재·문법·CSV/JSON 형식 검사만 통과했다면 기능 완료라고 판단하지 말아줘.
검증 후 변경된 파일은 다시 검증하고, PASS/FAIL/UNVERIFIED를 근거에 맞게 보고해줘.
~~~

### P08. 계획서·보고서·협업 기록 — 사실 기반 문서화

~~~text
실제 과제에서 요구한 문서와 파일명을 먼저 확인해줘. 요구하지 않은 문서를 무리하게 추가하지 말아줘.
현재 작업에서 실제로 확인한 목표·진행 순서·업무 질문·담당자 답변·중요 판단·검증 결과·한계를 바탕으로 문서를 작성해줘.
실행하지 않은 테스트, 받지 않은 답변, 확인하지 않은 성과를 사실처럼 만들지 말아줘.
기록이 필요하다면 ai-task-kit의 worklog를 선택적으로 사용하되, 내부 기록 파일을 과제의 제출 문서로 오인하지 말아줘.
읽기 쉬운 한국어를 사용하고 실제 과제 양식을 우선해줘.
~~~

### P09. 최종 제출 전 — 빠진 파일과 미검증 확인

~~~text
과제 지침의 필수 산출물·정확한 파일명·경로를 다시 읽고 현재 작업 폴더와 비교해줘. 도구 폴더가 제출 대상에 섞여 있는지도 확인해줘.
필요한 경우 ai-task-kit의 verify/preflight로 파일 존재·자료 형식·임시 파일·기록 상태를 보조 점검해줘.
실제 프로그램이 동작하는지 확인한 시험 결과와 아직 미검증인 부분을 구분해줘.
에디터 저장됨 표시, 저장 충돌, 실제 제출 대상 파일 목록은 내가 직접 확인할 항목으로 알려줘.
파일을 자동 삭제·외부 업로드·Git Push하지 말고, 최종 제출 버튼은 누르지 말아줘.
~~~

### P10. 연결이 끊기거나 작업을 재개할 때 — 실제 파일 상태에서 복원

~~~text
이전 대화가 모두 이어졌다고 가정하지 말고, 현재 과제 폴더의 README·파일·현재 저장 내용부터 다시 확인해줘.
이미 구현된 내용, 지금 실행 가능한 기능, 마지막으로 실제 확인된 검증, 누락된 산출물을 분리해줘.
문서나 기록에 없는 실행 결과·담당자 답변은 추측으로 복구하지 말아줘.
재시작으로 기존 작업물을 덮어쓰지 말고, 가장 중요한 미완료 작업부터 진행해줘.
~~~

### P11. 시간이 부족할 때 — 공식 타이머만 기준

~~~text
새로운 자체 타이머를 만들거나 남은 시간을 임의 계산하지 말아줘.
내가 확인한 Cofa 공식 타이머와 현재 과제 필수 요구사항을 기준으로, 선택 기능 개발은 중단하고 필수 산출물·핵심 실행 확인·저장 확인에 우선순위를 둬줘.
완료되지 않은 것은 솔직히 표시하고, 검증 없이 PASS로 바꾸지 말아줘.
남은 단계 중 지금 가장 중요한 작업 한 가지를 추천해줘. 최종 제출은 내가 직접 할게.
~~~

### P12. 외부 도구·저장소 사용이 막힐 때 — 우회 없이 계속

~~~text
공개 저장소 가져오기, Skill 읽기, 패키지 설치 또는 명령 실행이 허용되지 않으면 원인을 한 번 확인하고 우회하지 말아줘.
도구 설치를 반복하거나 별도 AI·API·원격 서버에 연결하지 말고, 현재 제공된 Codex와 허용된 기본 환경으로 과제를 수행해줘.
과제 지침부터 확인해 필수 기능을 구현하고, 실행할 수 있는 검증만 실제 수행해줘.
접속·감독·플랫폼 장애라면 Cofa 내 문제 신고를 이용하도록 알려줘.
~~~

## F. 사용 전 자체 점검

- 공개 저장소이며, **2차 예선 결과 통지 전까지 비공개로 전환하지 않을 것**.
- 프롬프트는 **응시 환경에서 공개 저장소를 가져와** 참조할 것. 개인 PC 클립보드·외부 메모 전사 금지.
- 실제 과제 원문과 공식 지시가 우선. 일반 템플릿이 결과물 전체를 대신하지 않음. 도구 폴더를 제출물과 분리하고 중복 지침 읽기는 피할 것.
- 최종 제출은 사용자가 직접. AI 금지 단계에서는 템플릿/AI 사용 중단.
- 이 레포에 시험 문제·답안·개인정보·로그·비공개 자료를 Git Push하지 않을 것.
