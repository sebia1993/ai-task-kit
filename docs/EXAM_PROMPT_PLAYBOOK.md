# Cofa 과제 수행 프롬프트 — Lite Mode 선택표

**이 파일은 가벼운 선택표(index)이며, P01~P12 상세 프롬프트 전체를 포함하지 않습니다.** `BOOTSTRAP.md`에서 시작하여 현재 과제 README·필수 결과물을 파악하고, 아래에서 **현재 필요한 번호의 개별 파일만** 읽으세요. 번호를 사용자가 하나씩 선택할 필요는 없습니다.

## 시험 규정과 출처

- **응시 환경에서 허용되는 경우에만** 공개 GitHub 저장소의 사전 제작 프롬프트를 가져와 사용합니다. 사용한 저장소는 **2차 예선 결과 통지 전까지 공개** 상태로 유지합니다.
- 개인 PC의 클립보드에서 사전 복사한 지시를 응시 화면에 붙여넣거나, **외부 메모를 보며 옮겨 적지 않습니다.**
- 실제 문제 원문·제출물·결과·업무 대화는 공개 GitHub로 Git Push하거나 외부 AI/API에 전송하지 않습니다. 외부 결과물로 과제 전체를 대체하거나 감독·권한을 우회하거나 자동 제출하지 않습니다.
- **후속 서술형 등 AI 사용 금지 단계에서는 이 문서와 AI를 사용하지 않습니다.** 실제 과제 안내 및 공식 가이드 9장이 우선합니다.
- 도구 `KIT`와 과제 `TASK`는 제출 파일이 섞이지 않도록 **허용된 분리 위치**에 둡니다. 과제 폴더 안에서 clone하지 않습니다. 막히면 우회하지 않고 기본 Codex를 사용합니다.

**선택 방법:** 과제 시작에는 P01, 구현은 P03, 데이터 과제면 P04, 웹이면 P05를 사용하고, 오류·검증·제출 단계에만 P06/P07/P09를 추가합니다. 보통 **한 번에 1~2개, 필요한 경우 최대 3개**만 선택하며 상황이 바뀌면 교체합니다. 읽지 않은 상세 파일은 적용했다고 주장하지 않습니다. 문서를 읽는 것만으로 코드가 구현·실행된 것은 아닙니다.

**빠른 대안:** 특정 상세 파일을 읽을 수 없다면 시간을 낭비하며 우회하지 말고, 이미 허용된 `SKILL.md`의 공통 지침과 실제 과제 README를 바탕으로 계속합니다. 그때는 해당 P번호를 '적용'했다고 표시하지 않습니다. **색인만 읽었으면 색인 확인, 상세 파일을 실제로 읽은 경우에만 해당 지침 읽기 확인**으로 구분합니다.

## 적용 이력 — 기존 두 줄 보고 유지

```text
적용 지침: P03(구현), P07(검증) | 플레이북: 해당 상세 읽기 확인
수행 근거: 허용된 실행 명령과 실제 테스트 출력 | 검증: PASS/FAIL/UNVERIFIED
```

읽기 실패 또는 실질적인 작업이 없었다면 다음처럼 정확히 보고합니다.

```text
적용 지침: 없음 | 플레이북: 색인만 확인/로드 실패/읽기 미확인
수행 근거: 실행 없음 | 검증: UNVERIFIED
```

**두 줄은 Codex의 자기 보고**이며 독립적인 감시·실행 보증이 아닙니다. 실제 파일·명령 출력과 대조하세요. `verify`와 `preflight`의 UNVERIFIED는 기능 미검증일 수 있으므로 실패로 오해하여 동일 검사를 반복하지 마세요.

## 최초 로드의 버전 확인 (가능할 때 1회)

Git 저장소이고 명령이 허용된 경우에만 다음을 실행합니다. `<KIT>`는 실제 도구 폴더 경로입니다.

~~~bash
git -C "<KIT>" rev-parse --verify HEAD
git -C "<KIT>" status --porcelain -- BOOTSTRAP.md .agents/skills/ai-task-kit/SKILL.md docs/EXAM_PROMPT_PLAYBOOK.md docs/prompts
~~~

실제 확인한 SHA와 지침 파일 변경 여부만 **최초 한 번** 보고합니다. Git 명령 사용이 불가하면 미확인으로 표시합니다. 커밋 확인은 파일 내용을 읽었다는 증거가 아닙니다. 이후 상황 변경 때는 **새 지침 파일만 읽고** 같은 문서를 반복하지 않습니다. 파일 접근 차단이나 응시 규정이 우선합니다.
