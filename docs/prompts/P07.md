# P07. 검증 — 파일이 있다는 것과 동작한다는 것을 구분

> **선택형 지침:** 실제 과제 상황에 이 번호가 필요할 때만 읽습니다. 공개 저장소 자료 활용이 허용된 **과제 수행 단계** 전용이며, 해당 단계의 공식 지침이 항상 우선합니다. 개인 PC의 클립보드·외부 메모 전사, 비공개 자료 반출, 자동 제출 및 AI 사용 금지 단계의 활용은 금지합니다. 이 파일을 읽은 사실과 실제 실행·검증은 다릅니다.

## 상세 작업 지시

~~~text
현재 요구사항을 [요구 → 구현 파일/기능 → 검증 명령/방법 → 실제 결과 → 남은 한계]로 연결해줘.
개발 도중에는 **방금 변경한 기능의 관련 테스트 또는 작은 실행 예제**부터 확인해줘. 주요 필수 기능 완료 후 및 제출 전에는 **전체 필수 요구사항과 관련 회귀 테스트**를 종합적으로 확인해줘. 입력이나 공식 테스트를 수정하지 마.
파일 존재·문법·CSV/JSON 형식 검사만 통과했다면 기능 완료라고 판단하지 마. 특히 verify/preflight의 UNVERIFIED(종료 코드 2)는 기능 미검증이라는 뜻이지 실행 실패가 아니므로, 같은 파일 검사만 반복하지 말고 실제 기능 검증으로 넘어가줘.
웹 과제라면 필요한 입력·버튼·검색·저장과 실제 결과를 확인해줘. 빈 결과·입력 오류 안내, 글자·버튼·표의 잘림·겹침도 확인할 항목으로 정리해줘. 화면 조작은 내가 내부 Browser에서 직접 확인하고, 네가 보지 못한 화면 상태는 미검증으로 구분해줘. 관련이 없는 과제에서는 웹 점검을 추가하지 마.
검증 후 변경된 파일은 다시 검증하고, PASS/FAIL/UNVERIFIED를 근거에 맞게 보고해줘.
검사 완료 뒤 파일이 바뀌지 않았고 새 증거가 없다면 동일 검사를 불필요하게 재실행하지 마. 검증 범위와 한계를 정확히 보고해줘.
~~~
