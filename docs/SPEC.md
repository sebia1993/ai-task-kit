# AI Task Kit — Exam Edition 설계 확정안

## 목적과 승인 범위
사용자가 이 대화에서 승인한 설계를 구현한다. 개발 지식이 부족한 응시자가 허용된 과제 수행 단계에서 플랫폼 내장 Codex를 지휘하도록 돕는다. 후속 서술형 답변, 학습·퀴즈, 외부 AI, 자동 제출은 범위 밖이다. 특정 대회의 공식 도구 또는 합격 보장 제품이 아니다.

## 선택한 접근
Superpowers 전체 설치, 대형 Python 프로젝트 병합, 별도 GUI 대신 **독자 작성한 짧은 Skill + 표준 라이브러리 기반 검사 도구**를 채택했다. 원본 프로젝트의 코드와 스킬 문장을 복제하지 않는다. 검증 우선·원인 조사·작은 작업 단위라는 원칙만 참고한다.

## 구조
- `BOOTSTRAP.md`: 자동 Skill 탐색 실패 때 직접 읽을 진입 문서.
- `.agents/skills/ai-task-kit/SKILL.md`: 요구 분석, 실행, 검증, 복구, 한국어 판단 안내.
- Skill 내부 `scripts/taskkit.py`: 독립 실행 CLI. 인터넷/모델/쉘 호출을 구현하지 않는다.
- `kit.py`: 동일 CLI의 저장소 루트 진입점.
- `docs/CODEX_WORK_ORDER.md`: 다음 Codex 작업자가 읽는 개발·검증 작업지시서.
- `evals/SCENARIOS.md`: 실제 모델 비교와 플랫폼 검증용 시나리오. 미실행 결과를 만들지 않는다.

## 9개 핵심 기능
1. 과제 분류와 요구사항 정리: 파일 탐색은 프로그램, 의미 해석은 Codex가 담당한다.
2. 작은 필수 기능부터 실행하는 지침. 기존 과제의 기술 스택·파일 경로를 우선한다.
3. 짧은 한국어 판단 안내. 일반 기술 결정은 진행하고 업무 의미 변경·파괴적 작업은 확인한다.
4. 안전한 환경/자료 검사: 경로 이탈·심볼릭 링크·무한 탐색·과대 파일 방지.
5. 검증과 오류 분석: 형식 검사와 실제 기능 검증을 구분한다.
6. 오류 재시도 관리: 공식 타이머만 사용하며 자체 시계·시간 입력은 없다. 동일 오류 실패를 수동 기록하고 2회 이상이면 재판단한다.
7. 제출 준비: 필수 경로·내용·문법 확인. 최종 제출은 사람만 수행한다.
8. 업무 기록: 요구사항·담당자 질문과 답변 반영·중요 판단·검증 주장 및 파일 식별값 관리.
9. 제출 전 점검·웹 미리보기: 로컬 파일·기록과 Cofa Browser의 서버 연결 확인을 돕는다.

## 구현 제약
Python 3.10 이상, 외부 Python 패키지 0개, 네트워크 요청·원격 로고·텔레메트리 0개. 원본 데이터는 읽기만 한다. 사용자가 명시적으로 요청한 오류·업무 기록 명령만 과제 폴더의 `.ai-task-kit/retries.json` 또는 `.ai-task-kit/worklog.json`에 기록한다. 과거 `session.json`은 변경하거나 자동 이관하지 않는다. 설정/승인/감독 기능을 우회하지 않는다. 검증 시 임의 Python·JS·SQL을 실행하지 않는다. 동작 테스트는 Codex가 플랫폼의 승인된 실행 도구로 별도 수행한다.

## 데이터 계약
UTF-8(BOM 허용) 기본, CP949/UTF-16은 명시 선택. 자동 누락 제거·0 채움·날짜 추측 금지. 파일 최대 8 MiB, 표 최대 100,000행·1,024열·행×열 2,000,000. 한계를 넘으면 전체 검사처럼 보고하지 않는다. JSON 중복 키·비유한 숫자 거부. CSV 열/행 폭·중복 헤더·필수 열·선택적 합계/고유키/날짜 검산.

## 완료와 미확인 구분
`PASS`는 출력의 scope에 한정된 검사 성공이다. `FAIL`은 확인된 위반, `UNVERIFIED`는 미검증/검사 제한이다. 종료 코드는 각각 0/1/2. 제출물 형식이 모두 정상이어도 실제 기능 검증은 자동 완료 처리하지 않는다. `worklog`의 PASS는 사람의 기록이며 `preflight`는 실제 저장·제출 완료를 확정하지 않는다.

## 실사용 전 게이트
로컬 자동 테스트, 깨끗한 복사본 테스트, 모델 동작 비교, Cofa 사전 체험을 구별해 기록한다. 이 환경에는 Codex CLI가 없어 모델 비교와 Cofa 호환성은 미검증으로 남긴다. 문서 정적 검사 통과를 에이전트 실전 성능 검증이라고 부르지 않는다.
