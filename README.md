# AI Task Kit — Exam Edition

**개발을 잘 모르는 응시자와, 허용된 과제 환경의 Codex를 위한 작은 작업 지침 + 로컬 검사 도구.**

별도 AI 모델, 정답 모음, GUI, 자동 제출 프로그램이 아닙니다. Superpowers 전체를 설치하지 않고 계획·원인 조사·완료 전 검증 원칙을 독자적으로 재구성했습니다. 외부 Python 패키지 없이 Python 3.10 이상에서 실행합니다.

> 시험 규정과 실제 문제 지침이 항상 우선합니다. 공개 저장소라고 모든 사용이 허용되는 것은 아닙니다. 후속 서술형 등 AI 금지 단계에는 사용하지 않습니다. **Cofa 실환경 호환성과 Codex 성능 개선은 아직 검증하지 않았습니다.**

## 가장 쉬운 사용법

### 1. 공개 도구를 허용된 응시 환경에서 가져오기

**가장 먼저 실제 과제 폴더(TASK)와 지원 도구 폴더(KIT)를 구분합니다.** Cofa에서 허용하는 작업 영역과 실제 제출 대상은 과제별로 확인해야 하며, 아래 구조는 예시일 뿐입니다.

```text
허용된 작업 영역/
├─ 과제 폴더/              ← 과제 소스·최종 제출물
└─ ai-task-kit/           ← 공개 보조 도구 (제출 대상 아님)
```

현재 위치를 확인한 후 **과제 폴더 바깥에 도구 폴더를 만들 수 있는 것으로 확인된 경우에만** 아래 명령을 실행합니다.

```bash
pwd
git clone --depth 1 https://github.com/sebia1993/ai-task-kit.git ai-task-kit
```

`pwd`는 위치 확인용입니다. **현재 위치가 실제 과제 폴더 또는 그 하위라면 여기에서 `git clone`을 실행하지 마세요.** 기존 폴더를 삭제하거나 과제 파일을 옮겨 해결하지 않습니다. Cofa가 별도 폴더를 허용하지 않거나 저장소 읽기를 차단하면 우회하지 말고 기본 Codex로 진행합니다. 별도 도구 설치에 3분 넘게 사용하지 않습니다.

이미 도구가 과제 폴더 안에 있다면 자동 이동·삭제하지 말고 **실제 제출 대상에 섞일 수 있음을 알려야 합니다.** `preflight`는 일부 전형적인 도구 폴더를 경고할 수 있으나, Git `.gitignore`나 도구의 경고가 플랫폼의 제출 대상에서 제외됨을 보장하지 않습니다. 최종 제출 목록은 사용자가 직접 확인해야 합니다.

### 2. 플랫폼에서 제공하는 Codex에 한국어로 요청

아래는 **Codex 대화 입력란에 넣는 문장**이지 터미널 명령어가 아닙니다. 경로가 다르면 실제 위치를 알려주세요.

```text
ai-task-kit/BOOTSTRAP.md를 실제로 읽고 그 지침에 따라 필요한 Skill과 플레이북을 최초 한 번만 확인해줘.
도구 폴더와 실제 과제 폴더를 구분하고, 과제 README와 필수 제출물을 먼저 확인해줘.
현재 상황에 필요한 P01~P12 지침을 스스로 선택하고 상황이 바뀌면 갱신해줘.
처음 로드할 때 실제 확인된 지침 파일 경로와 Git 커밋을 한 번만 알려줘(확인 불가 시 '미확인').
이후 각 응답 끝에는 적용 지침·파일 읽기 상태와 실제 수행 근거·검증 상태를 두 줄로 표시해줘.
문서를 실제로 읽지 못했다면 '로드 실패 · 적용 지침 없음'으로 보고하고 기본 Codex로 계속 진행해줘.
기술 작업은 직접 진행하되 중요한 업무 판단만 확인해줘. 최종 제출은 내가 할게.
```

**처음에는 BOOTSTRAP.md 하나만 읽으라고 요청**하면 됩니다. **Lite Mode**는 `BOOTSTRAP.md` → 공통 `SKILL.md` → 짧은 `EXAM_PROMPT_PLAYBOOK.md` **선택표**를 한 번 읽고, 필요할 때만 `docs/prompts/P01.md` 같은 **해당 상세 지침 하나**를 추가로 읽습니다. 처음부터 P01~P12 상세 문서를 모두 읽지 않습니다. 같은 세션에서 이미 확인한 내용은 재사용하고 새 세션·내용 소실 시에만 재확인합니다. 파일 경로는 실제 KIT 위치에 맞게 해석해야 합니다.

최초 로드 시 Git이 설치되어 있고 읽기 명령이 허용된다면 **실제 도구 폴더의 HEAD 커밋과 지침 파일 변경 여부**만 확인합니다. 확인하지 못한 커밋은 추정하지 않으며, 최초 로드 외에는 매 응답마다 Git 명령을 반복하지 않습니다. Skill 자동 등록은 필수가 아니며, 플랫폼이 파일 읽기를 금지하면 우회하지 않습니다. 맥북을 쓰더라도 원격 과제 환경이 macOS라고 가정하지 않습니다.

### 3. 사용자는 이 네 가지를 확인

“무엇을 만들었는지”, “실제로 어떤 검사를 했는지”, “어떤 결과가 아직 미검증인지”, “내가 결정해야 할 업무 조건은 무엇인지”를 확인합니다. Python·SQL 문법을 외울 필요는 없습니다. 터미널 명령 승인과 최종 제출은 직접 수행합니다.

## 프롬프트 자동 선택·사용 증거 확인

- [짧은 프롬프트 선택표](docs/EXAM_PROMPT_PLAYBOOK.md)를 최초 한 번 읽고, P01~P12 상세 문서(`docs/prompts/`) 중 현재 과제에 필요한 것만 Codex가 선택해 읽도록 안내합니다. 사용자가 번호를 직접 고를 필요가 없습니다. **상세 문서는 최초에 모두 읽지 않습니다.**
- 예: `적용 지침: P03(구현), P07(검증) | 플레이북: 해당 상세 읽기 확인` / `수행 근거: main.py 변경, unittest 5건 실제 통과 | 검증: PASS(해당 검사만)`
- **읽기 확인**은 해당 상세 지침 파일을 실제로 불러온 경우에만 표시합니다. **색인만 읽으면 적용 지침은 없음**으로 구분합니다. 최초 로드 때 확인한 파일 경로·Git 커밋(또는 미확인)을 1회 보고하되 Git SHA가 파일 읽기나 실제 사용을 증명하지는 않습니다. 파일 접근이 차단되면 빠르게 기본 Codex로 전환합니다.
- 이 표시 방식은 **에이전트의 자기 보고**이지 파일 접근이나 작업 수행의 독립적인 감시·검증 장치는 아닙니다. 실제 파일·터미널 출력과 대조하세요.
- 공개 저장소를 통한 파일 활용은 응시 환경의 허용 범위에서만 하세요. 개인 PC 클립보드 사전 복사·외부 메모 전사는 허용되지 않고, 사용한 저장소는 2차 예선 결과 통지 전까지 공개 상태를 유지해야 합니다.

## 180분 제한 과제를 위한 경량 개발 순서

1. **요구사항 우선순위:** 실제 과제 지침에서 **필수 기능/산출물**, **확인이 필요한 조건**, **선택 기능**을 구분합니다. 제공되지 않은 배점·조건을 추측하지 않습니다.
2. **초기 실행 경로 확보:** 기존 환경에서 가능한 한 빨리 **입력→처리→출력**으로 이어지는 작은 기능을 실제로 실행해 봅니다. 그다음 나머지 모든 필수 요구사항을 확장합니다.
3. **빠른 검증:** 개발 중 변경한 기능의 관련 테스트를 먼저 실행합니다. **종합 검증:** 주요 단계 완료 또는 제출 전에는 전체 필수 기능과 제출 형식을 확인합니다.
4. **오류 전략 변경:** 동일한 오류를 반복할 때는 근거를 바꾸어 원인을 재검토하고, 독립된 다른 필수 기능을 진행할 수 있는지 판단합니다. 필수 기능은 임의로 포기하지 않습니다.
5. **불필요한 작업 금지:** 기초 환경에 없는 패키지·DB·웹 서버, 장문의 반복 보고, 매 수정마다 `worklog`·`audit`·`retry` 호출을 기본값으로 만들지 않습니다. 검증하지 않은 것을 PASS라고 보고하지 않습니다.

**성능에 관한 제한:** 최초 로딩 문서량은 줄었지만, 실제 Cofa에서의 응답 지연이나 과제 완성 시간 개선율은 측정하지 않았습니다. 상세 문서 파일을 읽을 수 없으면 제한을 우회하지 않고 기본 Skill·Codex로 진행합니다.

## 포함 기능

| 구성 | 역할 |
|---|---|
| 핵심 Skill | 요구 분석, 작은 작업으로 구현, 실패 원인 조사, 실제 검증 |
| 한국어 판단 안내 | 상황·영향·권장 조치·필요한 한 가지 질문 |
| doctor / inspect | 환경과 파일 목록 확인, 과제 유형 후보 |
| audit | CSV/JSON 결측·중복·열·합계·고유값·날짜 검사 |
| verify | 필수 파일·비어 있음·Python 문법·자료 형식 확인 |
| explain | 오류를 확정하지 않고 한국어 조사 방향 제공 |
| retry | 시간 입력 없이 동일 오류의 실패 횟수를 수동 기록하고 반복 실패 시 접근 변경 권고 |
| worklog | 업무 질문·답변 반영, 중요한 판단과 검증 주장 기록, 파일 변경 감지 |
| preflight | 필수 파일·검토 후보·작업 기록 종합 점검 |
| Cofa 웹 참고 | 기존 서버의 포트·바인딩·미리보기 점검 안내 |

도구는 코드를 대신 생성하거나 테스트를 대신 실행하지 않습니다. 생성·실행·수정은 **플랫폼의 Codex**가 담당합니다. 검증 명령의 `PASS`는 해당 검사 범위에 한정됩니다. `verify`는 파일 형식이 모두 맞아도 기능 동작을 증명하지 못하므로 `UNVERIFIED`를 반환합니다. `worklog`의 PASS 역시 실제 명령을 실행해 확인한 결과가 아닌 **사용자가 입력한 검증 기록**입니다. `preflight`가 정상이어도 실제 제출 상태는 `UNVERIFIED`입니다.

## 도구 실행 예시 (KIT와 TASK 경로 분리)

`<KIT>`는 공개 지원 도구의 **실제 절대 경로**, `<TASK>`는 현재 과제 폴더의 **실제 절대 경로**로 각각 바꿉니다. 아래 예시는 어느 폴더에 있든 도구 파일을 과제 파일과 혼동하지 않도록 **절대 경로로** 실행합니다.

~~~bash
python3 "<KIT>/kit.py" doctor --root "<TASK>"
python3 "<KIT>/kit.py" inspect --root "<TASK>" --json
python3 "<KIT>/kit.py" audit --root "<TASK>" --file data/input.csv
python3 "<KIT>/kit.py" verify --root "<TASK>" --require main.py --require report.md
python3 "<KIT>/kit.py" retry attempt --root "<TASK>" --issue csv-error
python3 "<KIT>/kit.py" retry status --root "<TASK>"
python3 "<KIT>/kit.py" worklog status --root "<TASK>" --json
python3 "<KIT>/kit.py" preflight --root "<TASK>" --require main.py --require report.md
~~~

도구를 개발·관리하는 사람만 GitHub Actions와 같은 `unittest discover -s tests -v`로 KIT 자체의 회귀 테스트를 실행합니다. **시험 과제 기능 검증은 실제 TASK의 README·테스트 명령을 따릅니다.** KIT의 단위 테스트 통과가 TASK의 정답·제출 완료를 뜻하지 않습니다.

정확한 옵션과 검사 한도는 [도구 설명](.agents/skills/ai-task-kit/references/TOOLS.md)을 참고합니다. 코드 실행 실패를 숨기기 위해 입력·공식 테스트를 바꾸지 않습니다. 지원하지 않는 자료를 억지로 읽지 않습니다.

**시간 관리:** Cofa 공식 시험 화면의 타이머만 기준으로 사용합니다. 이전 `session start/status` 및 자체 남은 시간 계산 기능은 제거했습니다. `retry`는 수동 오류 횟수 기록만 수행하며 타이머나 오류를 자동 감지하지 않습니다. 기존 `.ai-task-kit/session.json`은 변경·삭제·자동 이관하지 않습니다. 새 기록은 `.ai-task-kit/retries.json`에 저장합니다.

선택표와 상세 파일은 [프롬프트 Lite Mode 색인](docs/EXAM_PROMPT_PLAYBOOK.md)에서 참조할 수 있습니다. 자세한 지침은 현재 필요할 때만 읽으며, 최초 인식에 불필요하게 시간을 쓰지 않습니다.

기록 기능을 쓸 때는 [요구사항·업무 질문·검증 기록 안내](.agents/skills/ai-task-kit/references/WORKFLOW.md)를, 웹 서비스 과제에서는 [Cofa 웹 실행 안내](.agents/skills/ai-task-kit/references/COFA_WEB.md)를 읽으세요. 둘 다 **필요한 상황에서만 사용하는 선택 기능**입니다. 과제 원문·비공개 파일·결과를 공개 GitHub에 올리지 않습니다. 로컬 `.ai-task-kit` 상태 폴더는 제출 산출물과 구분합니다.
